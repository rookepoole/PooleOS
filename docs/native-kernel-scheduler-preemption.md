# PKSCHED2 bounded scheduler preemption

PKSCHED2 is the Cycle 143 `N12-SCHED-PREEMPT-001` proof slice. It composes the PKSCHED1 fixed-capacity scheduler with the PKIRQ1 local-APIC/HPET path and demonstrates actual BSP timer and higher-priority wakeup preemption. It is an opt-in QEMU development profile selected by `development-scheduler-preempt` and selector 16; it is not active in ordinary PooleBoot builds.

The live profile creates four generation-safe tasks in one kernel address space. A two-tick quantum, one signal at tick 3, one current-task block at tick 4, and one cancellation wake at tick 5 produce the exact six-tick task trace `0,1,2,0,3,3` and causes `none,quantum,wake,block,wake,none`. The interrupt gate enters IST1 with IF clear, validates the complete 176-byte normalized frame, saves all 15 general registers plus vector/error and IRET state, runs the scheduler while holding its bounded owner-token lock, acknowledges the APIC, and substitutes a private incoming frame only when a switch is required.

Four private 16 KiB task stacks occupy the lowest 64 KiB of the 144 KiB guarded retained kernel stack. The remaining upper 80 KiB is reserved for kernel entry and launcher execution. Runtime checks require page and 16-byte alignment, exact non-overlap, canaries, a current launcher RSP in the upper region, and support the architecturally valid empty-stack case where saved RSP equals the exclusive task-stack top. All four task stacks are zeroed and read back after retirement.

The six live interrupts save six frames, restore four alternate frames, issue six EOIs, enter every task exactly once, preserve one CR3 and unchanged FS/GS/kernel-GS bases, and return through the exact two-transition assembly launcher. Cleanup masks the timer, retires controller and contexts, tears down all tasks, releases the scheduler lock, restores APIC/PIC/HPET state, revokes temporary MMIO, and halts with no signature, authority, action, or production claim.

Qualification is generated by `python tools/qualify_native_kernel_scheduler_preempt.py`. It requires 189 kernel host tests, a three-receipt Rust host probe checked against an independent Python scheduler model, two byte-identical media generations, two fresh-variable qemu64/OVMF runs, exact marker/screenshot/PBP1 agreement, and 25 hostile-control categories. The authoritative artifacts are `specs/native-kernel-scheduler-preemption-contract.json` and `runs/native-kernel-scheduler-preemption-readiness.json`.

This receipt does not prove live AP dispatch, cross-CPU migration, ring 3, process address-space switching, per-task FS/GS/xstate/debug/PMU ownership, a general timer wheel, deferred workers, target hardware, N12 exit, release readiness, or production readiness.
