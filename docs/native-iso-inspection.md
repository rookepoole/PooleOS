# Native ISO Architecture Inspection

Requirement: `ADD-N0-ISO-INSPECTION-001`, N0.8 with N39 integration.
Flag: `FLAG-N0-ISO-INSPECTION-001`, open until full supported media coverage,
independent verification and release-gate integration are qualified.

Implement read-only inspection of actual ordinary-file ISO bytes. The initial
optical profile has one ISO9660 namespace, one EFI no-emulation El Torito entry,
and a mirrored FAT32 boot filesystem. Reject unsupported alternative namespaces,
hybrid/system-area code and multiple boot entries instead of ignoring them.
Bound input size, directory depth, entry count and allocation chains. Detect
extent aliasing, endian disagreement, broken checksums, duplicate names, directory
cycles, FAT disagreements, cross-linked chains and unreferenced allocations.
Inspect hidden files as files, not as an exclusion from policy.

Apply the unchanged architecture policy to ISO and EFI file names and content.
Keep their namespaces distinct; required native objects must be in the EFI tree
for this initial profile. A structural success does not satisfy required-file
policy, verify signatures, prove authorship or qualify a boot.

Exit for the first implementation: actual retained demo image can be structurally
inventoried, its missing production objects are reported, synthetic compliant
media passes the scoped policy, and independent malformed/prohibited-payload
mutations reject. Never modify the input image or touch a block device.

Sources consulted on 2026-10-07:

- [UEFI 2.11, media access, section 13.3.2.1](https://uefi.org/specs/UEFI/2.11/13_Protocols_Media_Access.html): EFI optical boot uses a no-emulation FAT image and platform EF. Search-index text was available; direct HTML retrieval returned 403.
- [ECMA-119, sixth edition, December 2025](https://ecma-international.org/wp-content/uploads/ECMA-119_6th_edition_december_2025.pdf): ISO volume descriptors, directory records and paired path-table encodings.
- [Microsoft FAT Specification, 2005, Stanford-hosted copy](https://www.scs.stanford.edu/~zyedidia/docs/_other/fat.pdf): BPB, cluster-chain and directory-entry encodings. This is an authored specification copy, not a new license or rights determination.
- [pycdlib author documentation](https://clalancette.github.io/pycdlib/example-walking-iso-filesystem.html): an independent ISO authoring/inspection reference. Tests use the existing pinned host-only wheel; it is not an OS foundation or media payload.

Remaining production work includes GPT/hybrid layout, FAT12/16 and broader FAT32
profiles where required, additional namespaces, signed manifests and provenance,
native parser agreement, independently reproduced images and physical boot tests.
The supported profile must expand with the actual production layout. Unsupported
media must never receive a passing architecture verdict.

## Cycle 230 Findings

The retained demo yields 17 inventoried files, including 12 inner payloads whose
hashes agree with the original embedded manifest. Its EFI directory encodes the
root-parent dotdot cluster as 2 instead of zero. Inspection retains the inventory
but rejects conformance. Four required production paths are also absent; the demo
layout is not treated as production. A memory-only correction changes structural
admission, not the missing-object verdict. The original ISO remains unchanged.

Track the writer repair as `ADD-N5-FAT32-PARENT-001` and
`FLAG-N5-FAT32-PARENT-001`. Require independently checked generated bytes and
affected boot/media evidence before closure. The scanner is a bounded host tool,
not a native filesystem service. It supports long file aliases but rejects long
directory aliases in this first profile. Synthetic compliant fixtures contain
non-executable placeholders and are not OS images.

Nineteen new tests pass. The combined architecture suite passes 27 tests with one
expected Windows symlink-permission skip. Full candidate qualification and broader
format coverage remain separate. See [checkpoint](checkpoints/cycle230-native-iso-inspection.md).

## Cycle 231 Writer Repair

The host-side writer now encodes a root-parent dotdot cluster as zero, consistent
with Microsoft FAT specification sections 6.5/6.6. The bare inspector additionally
requires dot and dotdot in the first physical slots, directory attributes, zero
sizes and exact self/parent cluster values. Extended load-media inspection retains
its exact reconstructed-media comparison. Five new tests cover 17 field mutations,
four physical-slot mutations, deterministic independent inventory and extended
loader media. A new label-shadowing serialization error found during qualification
was repaired and covered by regression assertions.

Final focused testing passes 26/26. Two fresh loader and two fresh PooleBoot QEMU
runs pass, with unchanged native executable/payload records and newly generated
media hashes. Twenty-one dependent execution profiles still require replay;
aggregate source qualification fails correctly, and the N5 flag remains open.
The historical demo ISO is unchanged, not a corrected image. Broader format,
authentication, independent-builder and hardware claims remain unproved.
See [checkpoint](checkpoints/cycle231-fat32-directory-links.md).
