## Implemented

`native/kernel/src/reclamation/execution.rs` introduces the opaque PKEXEC1
`Dispatch` execution hold. Task lifetime remote dispatch acquires a pool reader
before scheduler queue mutation. The ticket is only protocol identity; copying
it or acknowledging scheduler completion cannot release the execution hold.

Ordinary drop, forgetting the handle and panic unwinding retain the pin.
Only consuming unsafe `confirm_quiescent` releases it. Its architecture caller
must establish that no CPU or resumable context can still use the resources,
and complete applicable invalidations. Scheduler state, timeout, ACK or an
offline indication alone is not sufficient. The hold does not guarantee stable
storage addresses or ownership of arbitrary allocations inside a payload.

Read-only scheduler admission preflight also repairs two reproduced defects:
transaction counter exhaustion and equal-priority bypass counter exhaustion
previously could fail after partial queue mutation. The fix is scoped to
dispatch admission, not a claim of atomicity for every scheduler operation.
