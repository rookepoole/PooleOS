# Native PKSMP4 Remote TLB Shootdown

PKSMP4 upgrades the bounded PKSMP3 two-vCPU Sandy Bridge profile from transport-only evidence to one real, AP-side TLB invalidation and one retired-generation release. It retains six fixed xAPIC vectors and the development-only fixed capability while expanding the processor-local extension to 344 bytes. Request and response checksums bind the AP-owned root, virtual address, retired and active generations, target and acknowledgement masks, old and new frames, observed values, invalidation count, final state, and error.

The proof starts APIC ID 1 through INIT-SIPI-SIPI and installs the old frame at AP virtual address `0x001FF000`. The AP reads `0x504B534D50344F4C` before the transaction so the old translation is resident. The BSP then exercises four inherited transport denials, sends generation 2 to offline APIC ID 2 with CPU mask `0x4`, observes one bounded timeout, and retries attempt 6 against APIC ID 1 with CPU mask `0x2`.

Before that retry, the BSP replaces page-table leaf 511 with a distinct new frame and restores its single temporary physical alias to the AP-local mailbox page. The AP validates the exact root, generation pair `1 -> 2`, mask, address, frames, and checksum before executing `INVLPG [0x001FF000]`. It reads `0x504B534D50344E57`, records one invalidation, acknowledges mask `0x2` and generation 2, and publishes a checksum-bound response. The BSP rejects reclaim before acknowledgement, accepts only the exact response, scrubs and releases the retired frame while the AP remains online, and restores the mailbox alias again before later IPIs.

The remaining operation classes are one reschedule observation, one fixed allowlisted no-op call, one diagnostic observation, one panic notice, and one stop. The run records six accepted and four denied deliveries, ten EOIs, xstate restoration, quiescence, final INIT parking, descriptor and page-table revalidation, capability revocation, and verified scrubbing of 32 AP runtime pages plus two shootdown frames. Allocation sequences are 2 for the AP image, 3 and 4 for the frames; release sequences are 5 and 6 for the frames and 7 for the AP image. The total release is 34 pages and 139,264 verified bytes.

The linked-image audit requires exactly one `INVLPG (%rax)` inside `poole_ap_ipi_trampoline_start..poole_ap_ipi_trampoline_end`, while the source audit binds it to the shootdown handler. The fixed capability remains development evidence, not a production authority system. PKSMP4 does not claim general multi-AP SMP, concurrent address-space replacement, multiple in-flight generations, INVPCID, CR3-reload shootdowns, arbitrary callbacks, a scheduler, x2APIC, hotplug, NUMA, physical-target evidence, or user, PGVM2, PDC, or PooleGlyph dispatch.

Qualification is generated by `python tools/qualify_native_kernel_smp_ipi.py`. It requires two fresh QEMU runs, exact normalized static markers, exact screenshots and PBP1 bytes, independent transport and shootdown models, a linked instruction audit, and 25 negative-control groups covering 169 rejected cases. The generated readiness artifact remains pre-production and closes only `FLAG-N9-SMP-SHOOTDOWN-001`; it does not close N8, N9, or a release gate.
