# Native PKSMP5 Multi-AP Runtime And Shootdown

PKSMP5 scales the bounded PKSMP1/2/4 path to one exact four-vCPU `SandyBridge,-avx` QEMU topology: BSP APIC ID 0 and legacy-xAPIC application processors 1, 2, and 3. Each AP owns a private 32-page below-1-MiB runtime, page-table root, guarded stacks, descriptors, IDT, xstate page, APIC mapping table, request/response mailbox, and two shootdown frames. Local CPU masks are derived as `1 << APIC ID`, producing `0x2`, `0x4`, and `0x8`; the aggregate target and acknowledgement mask is `0xE`.

The first startup attempt deliberately starts APs 1 and 2, targets absent APIC ID 4, and reaches one bounded timeout. The BSP final-INIT parks the two started APs, revokes aliases, scrubs and read-verifies all first-attempt runtime and frame pages, releases all three allocated resource sets, and requires fresh allocations before retry. The second attempt brings all three APs online simultaneously and revalidates their private GDT/TSS/IDT, guarded-stack, x87/SSE, and APIC-table state.

The current implementation records attempted real-AP starts before issuing
startup commands. A missing online acknowledgement therefore cannot cause a
possibly started AP to be omitted from final parking. The deliberately absent
APIC-4 target remains a frozen-topology negative case, not general discovery.

Each online AP receives one valid diagnostic request, one forged-capability denial, one generation-bound shootdown request, and one stop request. The AP-side trampoline validates the fixed development capability, vector, sequence, attempt, root, page, generations, frames, local mask, and checksum before executing exactly one `INVLPG` for virtual page `0x001FF000`. Three private acknowledgements are validated independently and folded into aggregate mask `0xE`; reclaim is rejected twice before all unique acknowledgements arrive. Those acknowledgements permit the generation-retirement decision, not immediate physical-frame release. PKRETAIN1 tokens keep old frames held through stop acknowledgements and final INIT parking of every started AP. Only after that boundary does the BSP end retention and scrub/release the old frames; remaining frames and runtime pages follow validated cleanup.

The successful lifecycle records nine accepted and three denied deliveries, twelve EOIs, three remote invalidations, three stopped/quiesced APs, final INIT parking, capability and alias revocation, and exact release of 96 runtime pages plus six frames. Both the partial attempt and successful attempt verify 417,792 bytes. Resource receipts permit allocator metadata-growth gaps but require every allocation and release sequence to be positive, unique, non-aliased, and causally ordered.

The linked-image audit requires exactly one `INVLPG (%rax)` instruction inside `poole_ap_ipi_trampoline_start..poole_ap_ipi_trampoline_end`; runtime execution count is three. The same linked scope contains a separate `INVLPG (%rbx)` for the successor lock profile, which PKSMP5 does not execute. Source controls require dynamic APIC-derived local masks, the multi-AP coordinator, explicit panic/stop counter bindings matching the frozen wire layout, and no arbitrary callback. The ordered aggregate root/frame receipts use domain-separated FNV-1a folds and cannot silently cancel to zero.

Qualification is generated by `python tools/qualify_native_kernel_smp_ipi.py`. It requires all 214 current kernel host tests, two fresh exact four-vCPU QEMU runs, 40 markers per run, exact screenshots and PBP1 bytes, independent lifecycle/transport/shootdown/resource models, a linked instruction audit, and 30 negative-control groups covering 243 rejected cases. The readiness artifact retains only the bounded `FLAG-N8-SMP-MULTI-AP-001` closure and predecessor bounded IPI/shootdown closures.

The Cycle 157 replay candidate is the unchanged Cycle 153 retention-capable
kernel, 517,784 canonical bytes in a 144-page image, SHA-256
`BDEECCB27B1B91406911F91169B9BF5F9DF0439BB39FA0E1882C07E1AF3B81EF`.
Exact-source replay is required. Source-bound lifecycle observations are not
the independent retirement/failure oracle or mandatory all-task/root/frame
ownership integration still required by N12.3.

PKSMP5 is not a general SMP or shootdown subsystem. It does not claim arbitrary topology, x2APIC, hotplug, NUMA, multiple sockets, address-space-wide invalidation, concurrent generations, INVPCID/PCID, scheduler ownership, migration or affinity authority, production capability minting, every failure interleaving, physical-target evidence, or user, PGVM2, PDC, or PooleGlyph dispatch. It does not close N8, N9, a release gate, or production readiness.
