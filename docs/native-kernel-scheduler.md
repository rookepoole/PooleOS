# Native PKSCHED1 Scheduler Foundation

PKSCHED1 introduces the first executable PooleKernel scheduler foundation. The allocation-free Rust core owns four fixed run queues and up to eight generation-safe task slots. It implements fixed-priority selection, round-robin ordering within an equal-priority cohort, a seven-dispatch maximum equal-priority bypass bound, hard affinity, runnable-only migration, runtime accounting, exact cancellation and timeout wake delivery, and teardown of dormant-independent active task ownership.

The synchronization subset contains a bounded atomic owner-token raw spinlock, a checked atomic reference count, and one fixed sleeping mutex with direct one-level priority inheritance. Recursive lock acquisition, non-owner unlock, stale task generations, duplicate run-queue entries, invalid affinity, overflow, underflow, and invalid context-switch preconditions fail closed. This is a bounded foundation, not a complete lock or scheduler subsystem.

The host-only `pksched1-probe` executes a deterministic 4,096-step, eight-task, four-CPU trace. An independently implemented Python scheduler replays the same externally frozen operations and must match all final task states, 1,761 dispatches, 2,334 migrations, per-task dispatch/runtime counters, and snapshot checksum `0x23B76E2F80E2B747`. Separate receipts cover exactly-once cancellation/timeout delivery, direct priority inheritance and handoff, and eight rejected context-switch mutations.

Selector 15 is an opt-in QEMU-only BSP profile. Two same-priority kernel tasks alternate for eight dispatches on separate 16 KiB static stacks. The machine-code switch saves and restores `RBX`, `RBP`, `R12`-`R15`, `RSP`, `RIP`, and `RFLAGS`; the proof requires sixteen machine transitions, four runs per task, unchanged CR3 and FS/GS bases, IF clear, intact stack canaries, and zero register errors. Both task stacks are cleared after their contexts are retired.

The linked-image audit confines the switch implementation to the named `poole_scheduler_context_switch..poole_scheduler_context_switch_end` scope and rejects x87/SIMD/XSAVE, control-register writes, MSR writes, debug-register access, interrupt enablement, syscall, I/O, and indirect control transfer. The live path holds the scheduler spinlock throughout the cooperative task exchange and releases it only after state and cleanup validation.

The existing `PooleScheduler.tla` model remains a predecessor safety model with three tasks, one CPU context, a model-specific bypass bound of two, and no liveness claim. PKSCHED1 cross-checks overlapping wake, priority, inheritance, and teardown behavior but does not claim full refinement, complete state-space coverage, temporal liveness, or equivalence between the model and the larger implementation.

Qualification is generated by `python tools/qualify_native_kernel_scheduler.py`. It requires the complete kernel host suite, the four-receipt Rust/Python oracle comparison, source and linked machine-code audits, two fresh media generations, two exact QEMU/OVMF runs, exact marker/frame/PBP1 agreement, and all frozen hostile controls.

PKSCHED1 does not implement interrupt-driven preemption, live AP dispatch, cross-CPU migration, wakeup preemption, per-CPU idle tasks, address-space or ring-3 switching, per-task FS/GS, full xstate/debug/PMU switching, chained inheritance, general sleeping locks, IRQ-save/NMI-safe locks, topology balancing, hotplug, NUMA, tickless idle, latency targets, watchdogs, or a PDC policy hook. It does not close N12, target-hardware qualification, signing, release promotion, or production readiness.
